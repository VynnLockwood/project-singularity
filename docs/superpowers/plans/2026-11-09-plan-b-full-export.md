# Plan B: full Postgres export (structure plus data) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /api/schema/export?schema=master&data=0|1` returns one `.sql` file that a Postgres admin can load into an empty database to recreate the designed schema (and, with `data=1`, its rows). The Schema tab gets a Download control with an "Include data" toggle.

**Architecture:** Read the structure straight from the Postgres catalogs through the read-only role (`pg_get_constraintdef`, `pg_get_expr`, `pg_get_indexdef`), so constraints, defaults and indexes are exact. Render DDL with small pure functions. Stream data with the server's own `COPY ... TO STDOUT` (psycopg `cursor.copy`), which already produces the COPY text format (`\N`, tab, `\\`), inside one `REPEATABLE READ READ ONLY` transaction so the file is a consistent snapshot. Counts are taken first in that same transaction, so the row cap can answer 413 before any byte is sent.

**Tech Stack:** Django (StreamingHttpResponse), psycopg 3, pytest with scratch Postgres (`tests/pgsetup.py`, real restricted roles), `psql` for the round-trip test, Next.js with Vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-database-tab-design.md` (section 2, Plan B; limits table in section 5).

## Global Constraints

- Endpoint: `GET /api/schema/export?schema=<name>&data=0|1`; defaults `schema=master`, `data=0`. Structure: any signed-in role. `data=1`: editor and up; a viewer gets 403.
- Response: `text/sql` attachment named `singularity-<schema>-<yyyymmdd>.sql`, streamed.
- File order: (1) header comment (generator, date, schema, data included or not, row counts); (2) `CREATE SCHEMA IF NOT EXISTS "<schema>";` and `SET search_path`; (3) per table `CREATE TABLE` with columns, types, `NOT NULL`, defaults, `GENERATED BY DEFAULT AS IDENTITY` (or `ALWAYS` as in the source), `PRIMARY KEY`, inline `UNIQUE` and named `CHECK` constraints; (4) `COMMENT ON TABLE/COLUMN`; (5) with data, per table in dependency order `COPY "<schema>"."<table>" (cols) FROM stdin;` rows, `\.`; (6) after data, `ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY ...` with the source `ON DELETE`/`ON UPDATE`; (7) `CREATE [UNIQUE] INDEX` for indexes not backing a constraint; (8) with data, identity fix with `setval(pg_get_serial_sequence(...), ...)`.
- Every identifier double-quoted with embedded quotes doubled (reuse `_ident` from `schema/export.py`); no user text is ever placed in SQL unescaped.
- Data is read through the read-only role in one `REPEATABLE READ` transaction, streamed, never loaded whole into memory.
- Cap: `limits.maxExportRows`, default `1000000`, tunable range `1000` to `20000000`. Over the cap: HTTP 413 with a message naming the table that crossed it; nothing is streamed.
- Audit: each export that starts writes `schema.export` with schema, data flag and row counts (through `audit.models.record`).
- Tables with no columns are skipped. Singularity's own tables (`singularity` schema, Django tables) never appear: only the requested schema is read.
- The exported file keeps the source schema name (no renaming).
- Out of scope: sampled or partial data, `pg_dump`, schemas other than the ones `allowed_schemas()` returns (today only `master`; Plan C widens it).
- Tests: the full backend suite has pre-existing failures. Capture the failing list before Task 1 (`pytest -q 2>&1 | grep -E "^(FAILED|ERROR)" | sort > /tmp/baseline-b.txt`); no new failures. Frontend baseline: `npx vitest run` all passing, `npx tsc --noEmit` clean.
- Commits: no attribution lines; author is the repo's configured user (VynnLockwood).

## Review Focus

- Names that need quoting (`order`, `we"ird`, mixed case, spaces) in table and column names, in every statement kind (CREATE, COMMENT, COPY, ALTER, INDEX, setval).
- Empty table with an identity column: after loading, the next generated id is 1 (not 2).
- Cell values: tab, newline, backslash, the literal text `\N`, Thai text, emoji; and NULL kept distinct from the empty string.
- Foreign-key cycle (A refers to B, B refers to A) and a self-referencing table: ordering must terminate and the file must load, because FKs are added after the data.
- Over the cap: the 413 arrives before any bytes are streamed and names the table; `data=0` is never limited by the cap.
- A column default that depends on a sequence (`nextval(...)`): fail with a clear 422 naming table and column, never emit a file that cannot load.
- `schema=` carrying quotes or SQL (`master"; DROP`) or an unknown name: 400, never reaches a query.
- Soft-deleted rows (`is_active = false`) are exported like any other row (the file is a backup, not a view).

### Task 1: Read the structure of a schema

**Files:**
- Create: `backend/schema/dump_model.py`
- Test: `backend/tests/test_export_model.py`

**Interfaces:**
- Produces:
  - `class ExportError(Exception)` with `.status: int` and `str(exc)` as the message.
  - `allowed_schemas() -> list[str]` returns `["master"]`.
  - `read_model(conn, schema: str) -> dict` where `conn` is an open psycopg connection with `dict_row` (as `ro_connection()` returns). Result:
    `{"tables": [{"name": str, "comment": str|None, "columns": [{"name","type","nullable": bool,"default": str|None,"identity": None|"always"|"by default","comment": str|None}], "constraints": [{"name","kind": "p"|"u"|"c"|"f","definition": str}], "indexes": [{"name","definition"}], "references": [str]}]}`. Tables sorted by name; columns in attribute order; tables with zero columns left out; `indexes` excludes indexes that back a constraint; `references` = other tables this table has FKs to (self excluded, sorted, only tables present in the result).

**Files:**

**Interfaces:**

  - `render_header(schema: str, include_data: bool, counts: dict[str, int], today: datetime.date) -> str`: comment lines only; contains the schema, the date as `YYYY-MM-DD`, the words `data: included` or `data: not included`, and one `-- <table>: <n> rows` line per count.
  - `render_structure(model: dict, schema: str) -> str`: `CREATE SCHEMA IF NOT EXISTS`, `SET search_path TO "<schema>";`, each `CREATE TABLE "<schema>"."<t>"` (column lines `"c" type [GENERATED {ALWAYS|BY DEFAULT} AS IDENTITY] [DEFAULT expr] [NOT NULL]`, then `CONSTRAINT "name" <definition>` for kinds `p`, `u`, `c` only), then `COMMENT ON TABLE`/`COMMENT ON COLUMN` with comment text escaped as a SQL literal (quotes doubled; use `E''`-free standard literal with `''`).

### Task 3: Stream structure and data

**Files:**
- Modify: `backend/schema/export.py`
- Test: `backend/tests/test_export_stream.py`

**Interfaces:**
- Consumes: Task 1 (`read_model`, `table_order`, `ExportError`), Task 2 renderers, `schema.conn.ro_connection`.
- Produces:
  - `EXPORT_TIMEOUT_MS = 600_000` (module constant).
  - `def open_export(schema: str, *, data: bool, cap: int) -> Export`. Opens a `ro_connection()`, starts a transaction (`BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY`, `SET LOCAL statement_timeout = EXPORT_TIMEOUT_MS`), reads the model, counts rows per table (`SELECT count(*)` with quoted identifiers) when `data` is true, and checks the cap. Raises `ExportError` (status 400 unknown schema via `allowed_schemas()`, 413 over cap with the table name in the message, 422 from the reader). On any raise the connection is closed first.
  - `class Export`: `.schema: str`, `.data: bool`, `.conn` (the open psycopg connection, exposed so tests can assert it is closed), `.counts: dict[str, int]` (empty when `data` is false), `.filename(today: datetime.date) -> str` returning `singularity-<schema>-<yyyymmdd>.sql`, `.chunks() -> Iterator[bytes]` yielding the file in the spec order (header, structure, then for each table in `table_order`: the `COPY ... FROM stdin;` line, the bytes produced by `cur.copy('COPY "<schema>"."<t>" (<cols>) TO STDOUT')`, then `\.` on its own line; then foreign keys, indexes, and the identity fix when data is true), and `.close()`. `chunks()` closes the connection when exhausted, on error, and when the generator is closed early.
- The cap counts all tables together; the table named in the 413 message is the first one, in `table_order`, whose running total passes `cap`.
